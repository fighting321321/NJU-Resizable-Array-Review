# Optimal resizable arrays

## 问题提出

如何解决可变长数组的空间分配问题？一个很典型的问题是：我现在内存分配满了，但是又有新元素，这时候我们不能直接在原有内存后面直接申请，因为可能存在已经被使用的。所以必须重新申请一块更大的内存。在这里，我们可以把这个问题拆分为 **机制** 和 **策略**

**机制：**

1. 提供固定大小的存储block
2. 存储block可以存放数据或者指针
3. Grow操作：申请新块
4. Shrink操作：删除末尾元素释放空块

**策略：**

1. block大小？
2. 指针层数？Grow中的block大小？
3. Shrink什么时候拆，什么时候rebuild

采用这两种分离视角定义问题，有助于理解。

已有实际应用成熟的做法是 Doubling，策略是：满了就开两倍的空间，grow均摊 $ O(1) $，访问也是相同的。标准倍增算法可以做到 $ O(N) $ 空间和 $ O(1) $ 的时间

本文的目标是：能否让空间为 $ N+o(N) $，同时保持$ O(1) $ 访问？

## 传统策略说明

According to Wikipedia [16], the geometric expansion/shrinking technique, with growth factors ranging from 1.25 to 2, is used to implement Java’s ArrayList, Python’s PyListObject, C++ STL’s Vector and more.

实际上这些传统策略可以归结为一种扩容策略，假设每次数组满后，增长因子为 $ (1+\alpha) $，那么新数组刚扩展完毕时浪费率为 $ \frac{\alpha}{1+\alpha} $，但是， $ \alpha $ 也不能无限小，当其越小时，时间开销越大，因为平均复制次数增多了，假设数组容量为$ C $后触发 grow，新容量变为$ C^' = (1+\alpha)C $，每个操作的成本为 $ 1/\alpha $

事实上，作者也讨论了，是否可以用 N + o(N) 的空间存储一个大小为 N 的可变长数组，同时每个操作仍保持 O(1) 时间？有文献指出可以使用N + O(√N) 空间进行实现，并且还证明了这种复杂度在某种意义上是最优的。

但是，如果再次区分两种空间：一是存储一个当前大小为 N 的可变长数组所需的空间（支持 O(1) 最坏情况时间的检索和修改操作），二是临时增加或减少数组大小时可能需要使用的空间（O(1) 摊还时间）。可以打破前面的下界。怎么理解这两种空间，我的理解是：

(1) 存储空间：数据处于稳态或者静态时，占据的内存总量，该空间需要最多 $ O(1) $ 时间进行随机访问和修改
(2) 临时空间：执行一次 grow 或者 shrink 时，除了存储空间外临时占用的空间，操作完成后立即释放，反应resize的峰值空间占用

现在这两种空间描述还比较模糊，后面到了算法讲解部分可以真正理解这两种空间。

Brodnik等人通过这种方式打破了下界：：存储一个数组只使用 N + O(N^{1/3}) 空间，而调整大小时临时使用 N + O(N^{2/3}) 空间。

## Resizable arrays

定义 Resizable arrays 为支持以下操作的抽象数据类型：

A ← Array()
创建一个空数组并返回。

A.Length()
返回数组 A 当前的元素个数（长度）。

A.Get(i)
返回数组 A 中第 i 个元素（下标从 0 开始）。
前提条件：0 ≤ i < A.Length()。

A.Set(i, a)
将数组 A 中第 i 个元素修改为 a。
前提条件：0 ≤ i < A.Length()。

A.Grow(a)
将数组 A 的长度增加 1，并在新增加的最后一个位置存入元素 a。

A.Shrink()
将数组 A 的长度减少 1，丢弃其最后一个元素。

注意：该数据结构只允许再数组末尾进行增加或者删除。假设内存管理系统允许分配和释放任意大小的固定长度数组。假设每个此类调用仅花费常数时间。如果分配或释放大小为 N 的固定长度数组需要 O(N) 时间。可调整大小的数组的实现必须使用动态分配的固定长度数组的集合，称为块。这些块要么是数据块，包含可调整大小的数组，要么是索引块，包含指向其他块的指针，或者是辅助块，包含数据结构使用的辅助信息。本文提出的所有数据结构都是这种形式。除了称为主索引块的一个索引块之外，每个块都必须由索引块之一中的指针指示，否则该块将无法访问。数据结构使用的空间是所有分配的块的长度之和。

作者围绕两种空间给出了以下定义：

**定义 2.1**（$(s(N), t(N))$-实现）。设 $s(N), t(N)$ 为两个非递减函数。一个可变长数组数据结构称为 $(s(N), t(N))$-实现，如果它存储大小为 $N$ 的数组时最多使用 $N + s(N)$ 空间，而在对大小为 $N$ 的数组执行 grow 或 shrink 操作期间最多使用 $N + t(N)$ 空间。



## Previous works

### 基础数据结构

精确分配：即新到来的元素，如果当前数组已满，则扩展至 $ N+O(1) $，但这种方式有很大的问题，一方面摊还成本为 $ \Omega(N) $，另一方面临时空间峰值可达 $ 2N + O(1) $

几何分配（geometric expansion/shrinking）：该策略为先前讨论过的 $ \alpha $ 扩展策略

- **增长**：数组满时扩容至 $(1+\alpha)N$，摊销代价为 $\frac{1+\alpha}{\alpha}$。
- **收缩**：当负载因子降至 $1/(1+\alpha)^2$ 时，缩容至 $N/(1+\alpha)$，摊销代价为 $1/\alpha$。

因此，较小的 $\alpha$ 可以提高空间利用率，但会导致更高的摊销时间；反之，较大的 $\alpha$ 则牺牲空间换时间。

### The data structure of Sitarski.

这里提到HAT（Hashed Array Tree）

HAT 维护一个块大小 $ B $， 并且始终保持如下不变式：$$\sqrt{N} \leq B < 4\sqrt{N}$$

空间开销分析：

设实际存储的元素数为 $ N $，分配的总槽位数是：$$\left\lceil \frac{N}{B} \right\rceil \cdot B$$，未使用的空槽位数严格小于$ B $，总占用空间为：

$$S(N) = \underbrace{N}_{\text{实际元素}} + \underbrace{\left(\left\lceil \frac{N}{B} \right\rceil \cdot B - N\right)}_{<\,B} + \underbrace{B}_{\text{索引块}} + \underbrace{O(1)}_{\text{元数据}}$$

所以 $$S(N) = N + O(\sqrt{N})$$

显然，它的随机访问时间为$ O(1) $，

Grow操作分三种情况

情况 1：最后一个数据块未满，直接放入该块的下一个空槽位。

情况 2：最后一个数据块已满，但已事先分配了空数据块，使用该空块的第一位。

情况 3：最后一个数据块已满，且无空块，分配一个新数据块，放入。

每种情况的实际操作均为 O(1)。

全局重建与摊销分析

当： $ N=B^2 $，触发全局重建（因为满了）

此时 B = 2B 翻倍，将所有 N 个元素重新分配到大小为新 B 的数据块中，重建代价为 $ O(N) $，最大新的容量为 $ (2B)^2 = 4N $

在两次重建之间，经历了 $ 4N - N = 3N $的增量，也就是每次重建均摊到 $ 3N $个元素上，均摊代价为$ \frac{O(N)}{3N} = O(1) $，同时，重建的临时空间是按临时数据块处理的，也就是不是一次性复制，所以临时空间最多需要额外 $ O(\sqrt{N}) $
